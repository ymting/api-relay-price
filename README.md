# 中转站比价

把各家 API 中转站的「模型 / 分组 / 价格」抓下来存到本地，按模型归类，点开就能横向比价。
填好账户凭据（New API 管理令牌、Sub2API 面板令牌，或兼容 Cookie／账号密码）之后，首页还能直接看到**每个站充了多少、用了多少、还剩多少**，以及每个分组下**有没有 Key**。

## 怎么用（两步）

1. **双击 `启动服务.bat`** —— 会启动本地服务并自动打开浏览器（服务窗口别关，关了定时任务就没了）。
2. **看数据**：双击 `中转站比价.html` 也行，它只读快照；检测到本机服务在跑时会给出「打开完整功能」按钮，
   点一下跳到服务地址，改配置、手动采集都在那边操作（出于安全，`file://` 页面不再跨源读写接口）。

推荐直接访问服务地址 <http://127.0.0.1:8765>（最稳）。数据全部存在本地 `data/` 目录，
首页打开时只读本地快照；模型详情是否自动读取健康统计，可在「系统设置 → 通用设置」中选择，默认关闭。

> 如果双击 HTML 后顶部显示「未连上本地服务」，说明服务没开或端口不对，照横幅上的提示点一下就行；
> 只是看价格的话不用管它，快照照样能筛选比价。服务已经在跑但横幅显示「本地服务已运行」时，
> 说明页面只读，点「打开完整功能」即可。

## 采集什么时候才会联网

价格采集只在以下两种情况访问站点：

- **每天到点自动跑一次**（默认凌晨 3:00，可在「系统设置 → 定时设置」里改或关掉 —— 放夜里是为了避开站点高峰，对方服务器压力小些）
- **手动点「手动采集」**（全量或自定义，都要在弹窗里点一下确认按钮）

刻意这样设计的原因：频繁抓同一批站点容易被判定为爬虫、临时封 IP。所以：

- 打开页面、刷新页面都不采集；
- 采集是**串行**的，站点之间会等待一段时间（默认 2 秒，可在设置里调到 5~10 秒）；
- 建议一天 1~2 次就够，平时看数据用本地快照。

> 服务要开着才会触发定时；到点那一刻如果没开服务，这一次就跳过，不做补跑。想要开机就有，把 `启动服务.bat` 的快捷方式放进「启动」文件夹即可。

### 某个站点这次没抓到怎么办

**不会把它的历史数据洗掉。** 采集失败（超时、改版、被限流）时，这个站会**沿用上一次的结果**，
结果元数据上打 `stale` 标记，顶部也会写明「N 个站点沿用上次采集结果（XX）」—— 看得见是用旧数据，不会闷着。

两种例外，和以前一样**不动数据**：

- **所有站点都失败了**：不写盘。否则除了把「数据更新于」刷成当下、谎报新鲜，没有任何收益。
- **中途点了强制停止**：不写盘，本轮完全作废。

> 之所以强调这条：以前全量采集是「整份覆盖」，一个站超时就会把它的报价写成 0。现在不会了。

## 账户概览

首页账户概览采用**一行汇总 + 紧凑站点表格**：顶部突出总余额，并显示已使用、已充值合计；每个已启用站点只占一行，依次显示站点、余额、已使用 / 已充值、Key 数量、更新状态和本站操作。

- 点行末箭头展开账号、分组、登录方式、请求次数、充值记录等信息；账户金额重绘后保留展开状态。
- 点右上角「收起」只隐藏站点列表，保留汇总；再次展开可恢复本站操作。折叠与展开不触发联网或保存设置，收起状态在当前页面中保留。
- 每行直接提供「刷新账户」「采集本站数据」，进度、结果和停止按钮就在对应行中；顶部原有全站入口保留。窄屏可在表格内横向滚动，金额和按钮不挤成多行。

「已充值」优先取站点充值记录，成功零条显示 0；接口失败或分页未读全时保留上次完整充值数据，没有历史数据则显示「—」。历史快照原有的`余额 + 已用`估算仍标「≈」。充值与 Key 分别保存成功时间，余额更新但列表失败时显示「部分未更新」，展开可查看原因。金额可切 USD / 人民币。

没配凭据显示「未配置」、金额为占位 `—`；有凭据但尚无快照显示「待刷新」。刷新失败保留的旧快照显示「数据过期」，完整原因可悬停或展开查看。汇总只包含启用站点中成功读取的账户快照；一个都没接入时显示 `—`，不会拿 `$0.00` 充数。凭据修改和站点增删仍在「系统设置 → 站点设置」处理。

凭据可以按下面的优先级填，**越靠前越省事**（页面里的页签顺序就是这个）：

| 方式 | 怎么弄 | 适合 |
| --- | --- | --- |
| **管理令牌**（New API） | 在站点「个人设置 → 安全设置」自行生成一个管理访问令牌（注意：不是 `sk-` 开头的模型 Key），填进「站点配置」 | 能读账户、还能管理自己的 Key；缺某项权限时只会停用对应功能 |
| **面板 access / refresh token**（Sub2API） | 浏览器登录站点后从请求头里取 `access_token`；有 `refresh_token` 一并填上，过期会自动续期一次 | Sub2API 站点的账户与 Key 管理 |
| **模型 API Key** | 就是平时调模型用的那个 `sk-` Key | 只用来查"当前这个 Key 还剩多少"（Key 额度，不是账户余额） |
| Cookie（兼容） | 浏览器登录站点 → F12 → 网络面板 → 随便点一个 XHR 请求 → 请求头里复制 **cookie** 那一整行 | 站点开了密码加密 / 两步验证 / 人机验证时的兜底方式 |
| 账号密码 | 在「站点配置」里直接填 | 站点没做加密时的省事选项 |
| 都留空 | —— | 只是看价格，不需要余额和 Key 信息 |

历史行为保留：只有 Cookie／账号密码时，也仍按 **Cookie 优先、账号密码回落** 的顺序用。新凭据不会清空旧凭据 —— 两套可以同时存在，切模式也不丢。

凭据只写进本机 `sites.json`，不会外传；过期了重新复制一次即可。配好之后点页面右上角的**「刷新账户」**，或在首页对应站点行点「刷新账户」，只刷新这一站。

站点配置中切换 **newapi / sub2api** 会立即显示对应的凭据字段与填写说明，无需先保存；往返切换保留未保存的输入。
Sub2API 的账户功能只填 **access token** 即可，refresh token 用于自动续期，属于选填；模型 API Key 只用于当前 Key 的用量、额度。
标准 Sub2API：浏览器登录站点后按 F12 → 应用程序 → 本地存储 → 当前域名，`auth_token` 填入 access token，`refresh_token` 可填入 refresh token。
到期时间可留空，面板接口前缀通常保持 `/api/v1`；这两项位于「Sub2API 高级设置」。页面还提供从网络请求的 Authorization 获取 access token 的备选步骤。
Sub2API 的账户累计消费读取 `/api/v1/usage/dashboard/stats` 的 `total_actual_cost`（实际扣费），累计请求数读取 `total_requests`，不混用标准计费或单个 Key 的用量。

### Sub2API 支付、兑换与累计入账

账户展开区分别展示支付订单（`/api/v1/payment/orders/my`）与兑换历史（`/api/v1/redeem/history`），只读记录，不发起支付、提交兑换或退款。

- 「已充值」在 Sub2API 中表示**累计余额入账（退款前）**：只累计 `type=balance` 且 `status=used` 的兑换额度，含在线充值、兑换与赠送。在线支付到账也产生兑换记录，因此**不再叠加支付订单金额**；管理员调整与订阅记录单独显示，不计入余额入账。
- 实付现金读取已完成余额订单的 `pay_amount`，**按原始币种分别显示、保留退款前口径**；不与钱包额度相加，也不推算净付款。
- `refund_amount` 是**钱包额度**，不等同于退回的现金。仅已退款／部分退款订单进入退款额度统计；申请中、处理中或失败不算退款完成。缺少退款额度显示未知，不按零处理。
- 两个列表都要求完整分页和总数校验；旧版本只返回截断数组时标为不完整。同账户刷新失败或分页未读全，保留上次完整记录、累计值及原成功时间，没有旧数据则显示未知。成功读取空账本才显示零。
- 记录投影不保留兑换码、交易号及任意远端正文；真实余额、用量或列表错误仍显示「部分未更新」。

**凭据怎么看？** 令牌、密码这类输入框右侧有个**小眼睛（👁）**：

- **自己输入/粘贴完**，点眼睛就能切换明文/掩码，核对填得对不对 —— **纯前端切换，不发任何请求**
- **这一项之前存过**，默认显示 `********`，无需先点眼睛或移开鼠标；点眼睛会先把这一个字段从本机取回来再显示原值。星号只用于显示，不会作为凭据提交。
- **保存之后输入框不会变空**：刚填的内容、以及当前的明文/掩码状态都会留着，方便你接着核对或改动
- 隐藏**只由你点眼睛触发**，不会自动抹掉；想真正删掉某项，用旁边的「清空」再保存
- 预期账户 ID 是直接显示的数字/字符串，不需要眼睛
- Cookie 是整块文本框、没有掩码可切，所以它还保留「显示 / 隐藏」按钮

限制如下 ——

- 一次只取一个字段，不存在"导出全部凭据"的入口
- 只对本机页面开放（服务只监听 127.0.0.1，其它来源的请求一律 403）
- 取凭据只在日志里记"谁看了哪个字段"，**不记值**
- 明文不会出现在 `/api/state`、`/api/sites` 这些普通响应里（有专门的回归测试守着这条）
- 页面上显示的凭据只活在当前这个页面里，**刷新页面就没了**（不会写进浏览器存储）

### 有些站点只能靠 Cookie（脚本绕不过去）

登录前会先读站点的开关。遇到下面这几种，**脚本一定失败**，不是配置错了：

| 情况 | 站点的表现 | 怎么办 |
| --- | --- | --- |
| **人机验证**（滑块 / 验证码 / Cloudflare Turnstile） | 登录返回 `captcha token required` 或 `Turnstile token is empty` | 去浏览器手动登录一次（验证你自己过），把 cookie 复制过来 |
| **密码登录被关闭** | 站点开关 `password_login_enabled=false` | 同上，只能用 Cookie |
| **密码加密登录** | 站点开关 `password_login_encryption_enabled=true` | 同上，脚本不做加密 |
| **二次验证**（邮箱验证码 / 2FA） | 登录返回 `require_verification` 挑战 | 同上，脚本收不到验证码 |

这些情况下，站点配置里那张卡片会直接写明**卡在哪、该干嘛**；首页的账户行只显示一个短标签（例如「需要人机验证」），鼠标悬停能看到完整原因 —— 首页是看数的，不堆报错。

## 手动采集：全量 or 自定义

右上角「手动采集」打开弹窗，两种范围：

- **全量**：抓所有启用的站点、所有模型。适合每天定时那次，或者数据放久了想整份刷新。
- **自定义**：左侧勾站点、右侧勾模型（模型列表支持搜索，可切「全部 / 只看常用」），只抓你选中的组合。
  结果按「**站点 × 模型**」合并进现有数据，**没选到的部分原样保留**，所以可以随时只补某一个站的某一个模型。

弹窗里会实时告诉你这次要访问几个站、几个模型、大概多长时间；点「开始采集」后弹一个确认框，**点按钮确认就行，不用打字**。
采集过程中面板顶部有 **`3 / 6` 进度条 + 当前正在采的站点名**，下面才是详细日志。
采集过程中随时可以点**「强制停止」**——不用等当前站点抓完，正在等的站点会立刻中断，这一轮不会写任何数据。

采集进度面板可以中途关掉，任务会在后台继续跑；跑完页面自动刷新。

| **站点设置** | 增删改站点、填写凭据（管理令牌／面板令牌／模型 Key／Cookie／账号密码）、**本站代理**、本站接入模式与按功能覆盖；每张卡片各自保存，删除后立即落盘。切换凭据录入方式保留已填内容。 |
| **定时设置** | 是否每日采集、采集时间、采后是否刷新账户、站点间隔。保留已有定时时间，不会因新增模块改回默认值。 |
| **备份还原** | 把站点与通用设置导出成一个 JSON 文件，或从备份文件整体还原配置。可选是否带站点凭据、是否带访问保护。 |
| **运行日志** | 查看采集、账户、定时等日志；离开日志页签或关闭系统设置时停止轮询。 |

「手动采集」「刷新账户」「常用模型」保留首页顶部原位置，常用模型直接打开独立配置面板。系统设置只集中通用、站点、定时、备份还原和日志；展示币种也可在首页快速切换。

### 备份与还原

「系统设置 → 备份还原」把 **站点设置 + 通用设置** 打包成一个 JSON 文件下载，换机器、重装、Docker 与源码互迁都靠它。

- **导出默认包含站点凭据**（Cookie / 密码 / 管理令牌 / 模型 Key）：不含凭据的备份还原后还得逐站重填，等于没备份。勾掉后会导出一份不含任何明文的结构副本，可以放心分享，但还原时凭据要重新填。带凭据导出会先弹一次确认——文件里的明文谁拿到都能直接用。
- **「包含访问保护」** 只在已开启访问保护时可勾；勾了就连用户名和密码哈希一起备份，还原后需要重新登录。
- **还原是整体替换**：备份里的站点与设置覆盖当前配置，备份里没有的站点会被删除。选好文件后先做一次预检，显示站点数量、导出时间与版本，确认无误再点还原。
- **还原前会自动归档**当前配置到 `sites.json.versions/`、`settings.json.versions/`，真还原错了可以手工翻回去。
- 备份文件不合法（不是本工具格式、版本不符、站点超限或字段非法）会整份拒绝，不会只还原一半；写入中途失败会自动回滚到导入前的状态。

命令行下也可以直接备份这三个文件，见 `DEPLOY.md` 第七章。

「打开模型详情时自动刷新健康状态」默认关闭，开启并保存后下次打开详情生效。先显示缓存，再对当前模型在已启用 New API / Sub2API 站点上的原始模型名去重、按健康并发上限读取；完成一项就显示一项，同站同模型各分组共用结果，60 秒内复用统计。通用设置可分别调整健康和账户刷新并发数（1–16，默认 5）。自动与手动刷新共享请求队列。关闭或切换模型后停止尚未发起的自动请求；失败保留旧数据并提示原因。此功能只读统计，不发推理请求，不消耗模型调用额度，也不自动采集价格。

保存时若填了非法值（框架不支持、地址没带协议头、id 重复、代理不是 http:// 或 https:// 的主机:端口），服务端会拦下来，并在那张卡片下面告诉你哪一条被忽略了。保存结果就显示在对应卡片里，不用往上翻。**删除站点是删了就落盘**，不用再点保存。

### 代理怎么排优先级

每个站点的「本站代理」最优先；留空才看「通用设置」里的全局代理。全局代理有三种取法，在「通用设置 → 显示与网络」里选：

| 模式 | 行为 | 什么时候用 |
| --- | --- | --- |
| 直连 | 完全不走代理，连系统代理也不用 | 排查"是不是代理的锅"；网络本身就能直连站点 |
| 跟随系统代理 | 用操作系统当前的代理设置，端口换了自动跟着走 | 日常推荐。代理工具的端口经常变，选它不用手动改 |
| 手动配置 | 用下面填的固定地址 | 要指定某个固定端口，或系统代理没开但代理软件在跑 |

选「跟随系统代理」时，设置页会显示当前实际检测到哪个地址；系统没开代理时它会等同于直连，页面会直接说明。

优先级只有这一条规则：站点级 > 全局模式。采集价格、刷新账户、读写 Key、导出到 CC Switch 全部按它走，不会出现"某条路径偷偷用了别的代理"。

漏写协议头（例如只写 `127.0.0.1:7890`）会自动补成 `http://127.0.0.1:7890`；只支持 HTTP(S) 代理（本机不支持 socks）。

### 单个站点刷新与采集

首页「账户概览」的每个已启用站点行直接提供「刷新账户」和「采集本站数据」。前者只读取该站账户，并在行内显示进度和结果；后者确认后采集该站全部模型、分组报价，合并到本地，保留其它站点数据，也不改变手动采集记住的范围。

本站采集在行内显示进度和停止按钮，停止或失败保留旧数据；首页「手动采集」也可查看后台任务。停用/不存在站点不展示操作行。操作始终使用已保存配置，不会保存系统设置中的草稿；新增且尚无账户快照的已启用站点也会显示一行，方便单独刷新。表格金额重绘时保留操作区节点，进度和停止按钮不会丢失。

## 看价格

- 左侧按 **站点 / 计费方式 / 厂商 / 标签** 筛选；顶部搜索框支持**模糊匹配**，输 `cl opus`、`opus5`、`36flash` 都能找到对应模型。
- 排序可选：输入价低→高（默认）、输入价高→低、输出价、单次价、报价站点数、模型名。
- 点模型 → 弹出**居中的详情弹窗**，列出全部「站点 × 分组」的报价，低价排最前，最低那行高亮标「最低」。
- 点击某条站点报价，会在该行下展开**对应分组的 Key 列表**，显示名称、掩码和状态，可复制指定 Key 或一键导入 CC Switch。点「创建 Key」只需输入名称，分组沿用当前条目，默认永不过期且不限额度；创建成功自动复制完整 Key，再提示是否导入 CC Switch。
- **New API 模型近期状态 · 全组 / 24h** 与站点模型卡片使用同一口径：`GET /api/perf-metrics/summary?hours=24&recent_model=<站点原始模型名>`，按精确模型名读取成功率、平均延迟、吞吐量与近期采样。成功率排除业务拒绝，包含当前未结束的小时；延迟按毫秒/秒显示，吞吐量为 tokens/s，灰色采样条表示无数据。近期历史采样可能超出 24 小时，不会据此编造 24 小时总体成功率。
- 展开报价后可单独查看**本分组状态**，数据来自 `GET /api/perf-metrics?model=<站点原始模型名>&hours=24`；本分组真实失败不会被全组成功率覆盖。账号所属分组与有无 Key 单独显示，不作为模型连通性证明。点「更新模型健康」同时更新模型汇总和分组明细，60 秒内复用同版本缓存；部分失败保留相应旧数据并说明原因，成功返回无数据则清除旧汇总。更新不会调用模型或消耗推理额度。
- **Sub2API V2**：读取 `/api/v1/channel-monitor-v2/snapshot` 与 `/matrix`，精确过滤原始模型、`range=24h`，明细按 `platform_group_model` 分组。展示**账户可见分组的 24h 请求统计**，不宣称全站；成功率从 0–1 换算一次为百分比，覆盖不足单独提示。普通用户的请求数可能被清零，不能据此抹掉真实 0% 失败；无样本显示未知。TPM 为每分钟流量，不作为 tokens/s 生成速度。
- **Sub2API V1**：仅 V2 路径不存在或明确未启用／模式不符时，读取 `/api/v1/channel-monitors`。按 `primary_model` 精确匹配并展示**7 天探测可用率**；附加模型不借主模型汇总，多个监控不平均百分比。0% 且七天内无探测记录显示无数据，有近期失败记录才保留真实 0%。认证、权限、限流或格式错误不会被回退掩盖；历史探测与请求统计都不保证当前连通。
- V2 明细可能包含未匹配模型的空占位；仅在无模型、无样本、健康未知、无 RPM/TPM 流量且 `buckets=[]` 时跳过，不生成当前模型的分组数据。缺模型却有样本／流量、或返回其他模型时仍报协议错误。
- 勾上「只看账号所属 / 已建 Key 的分组」可筛选账号相关条目。
- 顶部可切换 **USD / 人民币**（汇率可改，自动记住）。

> 所有面板都是弹窗，按 `Esc` 或点右上角 `×` 关闭；弹窗尺寸按内容自适应，详情表压到刚好一屏能看完，不用横向拖滚动条。

## 一键导出到 CC Switch

[CC Switch](https://ccswitch.io) 是本地切换各家 API 供应商的客户端，支持 `ccswitch://` 深链导入。模型详情里点击站点报价，选目标应用，再点指定 Key 旁的**「一键导入 CC Switch」**即可：系统内部取明文、生成链接并自动唤起工具，用户不用再点一次生成后的链接。CC Switch 或浏览器自身的确认提示仍由用户处理。

创建与导入统一在站点报价展开区操作。导入使用当前条目的站点、分组和原始模型名；新建后的导入使用刚创建的 Key。系统无法确认外部应用是否完成导入，所以只提示「已请求打开」；浏览器拦截时可展开「导入详情与备用链接」重试或复制链接。

导入到 CC Switch 和 Cindy 的记录名称统一为 **`中转站名称-Key 名称-模型名称`**，例如 `云端网-我的编程Key-claude-fable-5-1`。Key 名称取站点中实际选中或刚创建的名称，模型取本站原始名；没有名称时使用「未命名 Key」。只改新生成的导入记录名，不重命名站点上的 Key 或客户端已有记录。Cindy 的模型后缀仅用于显示，导入仍不附带模型清单；超长名称继续遵守 Cindy 既有截断限制。

关键点是**模型名会用站点自己的原始名**：同一个模型在不同中转站的写法不一样（`claude-opus-4-5`、`[次]claude-fable-5`、`gpt-6-astra`……），表格里看的是归一化后的名字，导出时自动换成**该站点在那个分组下真正认的名字**，所以导过去就能直接跑。手动改过模型名或端点后，切站点不会再覆盖你的输入。

在条目中可选择目标应用，以及是否带上余额查询。余额查询脚本在导入链接中按 CC Switch 要求先 Base64 编码，再做 URL 转义。余额查询按平台生成：New API 使用已授权管理令牌及本站确认的额度换算，Sub2API 使用当前模型 Key 查询用量；仅有 Cookie 且拿不到有效授权时跳过并提示。

复制与导入通过同一个接口读取完整 Key：站点返回原始令牌时补齐 `sk-` 前缀，已经包含前缀时保持原样；不会把列表掩码当成明文使用。

导入过程中如果新建了 Key，结果会明确写明。指定某个 Key 导入时服务端会验证分组、启用状态、过期时间和模型限制，不会静默换成其他 Key。Key 明文仅用于本机复制和深链导入，不发送给第三方服务。

> 没装 CC Switch 也能生成链接（页面会提示没找到它的配置目录），装好再点同一个链接就行。

### Key 删除与操作速度

展开站点报价后，每个 Key 旁有「删除」按钮；确认后从该站点删除，立即同步本地 Key 列表、分组数量与账户概览。删除会让使用该 Key 的客户端失效，包含已经导入 CC Switch 的配置。站点未确认成功时保留列表并显示错误。

创建和删除只更新 Key 信息，不等待整站余额、充值记录刷新。连续复制、创建和导入在 120 秒内复用已经验证的身份，按站点完整配置、凭据版本、代理及接入策略隔离；失败会清缓存，配置变化后重新验证。账户刷新使用独立缓存，仍每轮读取真实余额。普通已有 Key 导入仍读取远端列表与明文；刚创建的 Key 可在这 120 秒内复用内存记录，减少立即导入时的重复列表和取 Key 请求。缓存不落盘，并核对会话、配置、凭据版本及账户绑定；修改或删除 Key、操作失败、凭据轮换后失效，重新读取真实名称、分组、启用状态、到期时间（含 Sub2API ISO 时间）及模型限制。站点外发生的变更可能在短缓存到期后反映，缓存不代表持续在线验证。

同一次自动创建导入复用刚读全的创建前列表，仍保留无 ID 回包的写后唯一回查与未知结果锁定；创建回包已含确认 ID 和有效明文时不再额外取一次 Key。Sub2API 优先使用当前报价提供的真实分组 ID，不再为显示名额外读取分组与倍率。余额脚本复用本轮身份，仍确认真实单位；各阶段独立 12 秒预算，交互不做一般网络自动重试，也不重放创建、删除。

导入成功立即打开 CCS，使用返回的掩码账户快照局部更新列表，不再等待额外账户读取；重复入口的在途导入会合并，后续再次导入指定同一个 Key。请求期间切换模型后，旧结果不改写新页面，也不会唤起旧模型配置。新建后若账户绑定变化，不把旧 Key 写入新账户，只提示刷新核对。

## 价格是怎么算出来的

站点返回的是倍率，不是标价。换算规则与 new-api 官方前端一致：

| 计费方式 | 输入价（USD / 1M tokens） | 说明 |
| --- | --- | --- |
| 按量 `quota_type=0` | `model_ratio × 2 × 分组倍率` | 输出价再乘 `completion_ratio`，缓存读写同理 |
| 动态表达式 `tiered_expr` | 按条件选出**短上下文那一档**的系数 × 分组倍率 | `p/c/cr/cc` 即输入/输出/缓存读/缓存写单价；表达式原文会保留 |
| 按次 `quota_type=1` | — | 单次价 = `model_price × 分组倍率`（USD / 次，不乘百万） |

余额的换算**以站点自己返回的 `quota_per_unit` 和币种为准**（读取 `/api/status`）。站点没给出换算依据或币种时，保留原始额度并把金额显示为未知，不套用旧的固定 `500000`。Sub2API 的 token 单价字段是 **USD / token**，入库前乘 1,000,000 换算成 USD / 百万 token。

| `sites.json` / `settings.json` | 站点清单（含凭据）与偏好设置（**都不进版本库**）；每次保存都会把上一版归档到 `.versions/`（保留最近 30 份 ∪ 30 天，同样含凭据，**已排除在版本库之外**）；主文件读不出来时会自动回退到 `.bak` 或归档里的最新一份 |
| `data/prices.json`、`prices.js`、`index.json` | 本地数据快照，网页只读这三个文件 |
| `data/accounts.json` | 各站的余额 / 用量 / Key 快照，页面只读 |
| `data/health.json` | 显式更新后的模型分组健康统计，本地缓存 |
| `data/write_operations.json` | Key 创建/修改/删除的操作记录（**不含明文凭据**），进程重启后据此对账 |
| `data/evidence_matrix.jsonl` | 「站点 × 功能」调用证据（提供者/模式/触发源/成败/耗时，**不含凭据**），用于判断某个功能能否停用旧 Cookie 兼容链路 |
| `tests/` | A–E 各阶段的合成专项测试（`python -m unittest discover -s tests`） |
| `bump_version.py` | 版本号维护：`--dev` 递增序号、`--release` 去后缀定版（`VERSION` 是唯一来源） |
| `diagnose_account_auth.py` | 只读比对账户鉴权形式，结果写 `logs/`，不发写请求 |
| `Dockerfile`、`compose.example.yaml`、`deploy/` | 容器镜像、Compose 样例、systemd unit 与 Caddy 反代样例 |
| `DEPLOY.md` | 完整部署手册：三种方式、排障、备份、给 AI Agent 的可执行步骤 |
| `docs/`、`memory/` | 设计文档与项目记忆（本机目录，已在 `.gitignore` 中排除，不随仓库分发） |

`index.json` 是轻量索引（压缩后约 8KB），首屏秒开；某模型的完整报价在点开时才按需请求。**采集价格.bat** 保留了命令行入口，不想开服务时用它可以手动跑一次采集；加 `--debug` 会多打印一行每个站点的逐功能诊断（提供者、端点、状态），排查"这个站的这个功能到底走没走通"时很有用，诊断只输出到控制台、不会写进快照。

## 本地版本管理

项目使用 Git，主分支为 `main`。在项目目录打开终端，常用命令：

```powershell
git status                         # 查看当前改动
git diff                           # 查看尚未暂存的改动内容
git add -A                         # 暂存改动（遵循 .gitignore）
git diff --cached                  # 提交前核对内容
git commit -m "说明本次修改"         # 保存一个版本
git log --oneline -10               # 查看最近十个版本
```

源码、启动脚本、站点配置模板、测试与 README 纳入版本管理。账号配置、偏好、备份、环境变量、私钥、数据快照、日志、本机 `_` 前缀自检脚本，以及 `docs/`、`memory/` 两个本机目录由 `.gitignore` 排除。这些被排除的文件需要单独备份，Git 无法恢复其历史。

### 分支与发布流程

`main` 只保留已发布的正式版本，日常改动全部在 `dev` 上完成。

| 分支 | `VERSION` 形态 | 镜像标签 | 何时构建镜像 |
| --- | --- | --- | --- |
| `dev` | `1.0.1-1`、`1.0.1-2`……（生产版本的 patch +1，末尾 `-n` 递增） | `dev-latest`、版本号、`sha-xxxxxxx` | 每次推送 `dev` |
| `main` | `1.0.1`（与发布标签一致，不带后缀） | `latest`、版本号、`sha-xxxxxxx` | 只在发布 Release 时 |

**日常开发**

```powershell
python bump_version.py --dev     # 1.0.1-1 → 1.0.1-2，提交前跑一次
git add -A
git commit -m "说明本次修改"
git push
```

推送 `dev` 后 CI 跑完整回归，镜像同时产出 `dev-latest`，可以直接拉来试。

**正式发版**

```powershell
python bump_version.py --release  # 1.0.1-3 → 1.0.1
git commit -am "发版 1.0.1"
git checkout main
git merge --ff-only dev           # main 只接受来自 dev 的快进合并
git push
gh release create v1.0.1 --target main --title "v1.0.1" --notes "变更说明"
```

只有发布 Release 才会构建正式镜像并打上 `latest`；`main` 的普通推送不产镜像。发版完成后回到 `dev` 推进下一轮：

```powershell
git checkout dev
python bump_version.py --dev      # 1.0.1 → 1.0.2-1
git commit -am "开始 1.0.2 开发"
git push
```

版本号由 CI 把关：`dev` 的 `VERSION` 必须是 `X.Y.Z-n`；Release 标签必须与 `VERSION` 完全一致且不带后缀，并且标签所在提交必须在 `main` 上。每次完成并验证一项修改后提交，才会留下新的版本；Git 不会自动保存每次编辑。

## 部署

三种方式，按场景选一种。完整手册（排障、备份、环境变量全表、给 AI Agent 的可执行步骤）见 [`DEPLOY.md`](DEPLOY.md)。

| 方式 | 适合 | 需要 |
| --- | --- | --- |
| Windows 本地 | 自己电脑上看数据 | Python 3.10+ |
| Docker Compose | 有 Docker 的 Linux 服务器，推荐 | Docker 24+ / Compose v2 |
| systemd + 源码 | 不想装 Docker；Debian / Ubuntu | Python 3.10+ |

三种方式的数据都在同一个状态目录里：`sites.json`（站点与凭据）、`settings.json`（偏好）、`auth.json`（登录密码）、`data/`（快照）、`logs/`。换方式只要把这个目录搬过去就能接着用；其中只有前两个值得认真备份。

> **容器部署必看**：开了访问保护却没有 `auth.json` 时，服务会以**退出码 1** 退出，容器反复重启。第一次启动前必须跑一次 `--init-auth`。

### Windows 本地

双击 `启动服务.bat` 即可。不设置 `RELAY_MODE` 时就是 `local` 模式：只监听 `127.0.0.1`、按 8765–8770 顺序找空端口、认证默认关闭。

### Docker Compose

```bash
sudo install -d -m 0700 -o 10001 -g 10001 /var/lib/relay-price   # 属主必须是 10001，否则启动即报权限错误
sudo mkdir -p /etc/relay-price
sudo cp compose.example.yaml /etc/relay-price/compose.yaml
# 把 compose.yaml 里的 RELAY_ALLOWED_ORIGINS / RELAY_ALLOWED_HOSTS 改成你的域名

cd /etc/relay-price
sudo docker compose run --rm -it app python server.py --init-auth   # 必须先初始化访问保护
sudo docker compose up -d
curl --noproxy '*' -fsS http://127.0.0.1:8765/healthz               # {"ok": true, "version": "1.0.0"}
```

镜像地址 `ghcr.io/ymting/api-relay-price`：`:1.0.0` 是当前正式版，`:latest` 跟随最新正式版，`:dev-latest` 是最新开发构建（功能最新但不保证稳定）。

业务端口只发布到 `127.0.0.1`，HTTPS 交给宿主 Caddy 反代（配置见 `deploy/Caddyfile.example`，其中 `/healthz` 对外返回 404）。示例里的 `command` 带 `--no-schedule`，核对时区与保存的计划后再删掉这一项。

### systemd + 源码

```bash
sudo install -d -m 0700 -o relay -g relay /var/lib/relay-price
sudo git clone https://github.com/ymting/api-relay-price.git /opt/relay-price/current
sudo cp /opt/relay-price/current/deploy/relay-price.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable relay-price

# 首次先初始化认证：--init-auth 也会取实例锁，所以要先把服务停着
sudo systemctl stop relay-price
sudo -u relay env RELAY_MODE=server RELAY_STATE_DIR=/var/lib/relay-price \
  RELAY_ALLOWED_ORIGINS=https://relay.example.com RELAY_ALLOWED_HOSTS=relay.example.com \
  /usr/bin/python3 /opt/relay-price/current/server.py --init-auth
sudo systemctl start relay-price
```

`RestartPreventExitStatus=2` 是必需的：退出码 2 表示状态目录已被另一个实例锁定，重启也不会成功。

### 环境变量

`server` 模式缺任意一项必需变量都会拒绝启动，不会悄悄退回代码目录：

| 变量 | 示例 | 说明 |
| --- | --- | --- |
| `RELAY_MODE` | `server` | `local`（默认）/ `server` |
| `RELAY_STATE_DIR` | `/var/lib/relay-price` | 配置、快照、日志、认证与实例锁的唯一目录 |
| `RELAY_ALLOWED_ORIGINS` | `https://relay.example.com` | 精确来源，不接受通配符或 `null` |
| `RELAY_ALLOWED_HOSTS` | `relay.example.com,127.0.0.1:8765` | 精确 Host（含端口） |
| `RELAY_HOST` / `RELAY_PORT` | `0.0.0.0` / `8765` | 容器内监听地址与端口 |
| `RELAY_AUTH_DEFAULT_ENABLED` | `1` | 仅首次没有 `auth.json` 时生效 |

可选：`RELAY_TRUSTED_PROXIES`（只有这些 TCP 对端可以提供 `X-Forwarded-For`，精确 IP，不支持网段）、
`RELAY_STRICT_PORT`（默认 1）、`RELAY_VERSION_KEEP` / `RELAY_VERSION_KEEP_DAYS`（配置归档保留，默认 30 / 30）、
`RELAY_LOCAL_ALLOW_NULL_ORIGIN=1`（仅本地模式临时回退，`server` 忽略）。

`local` 模式不接受 `RELAY_ALLOWED_ORIGINS`、`RELAY_ALLOWED_HOSTS`、`RELAY_STRICT_PORT`，设了会直接报错 —— 这是防止本机模式被误配成对外开放。

### 访问保护

服务器模式默认要求登录（单账号）。**首次部署必须先初始化**，否则服务起不来。

**怎么开启 / 关闭**

| 场景 | 怎么做 |
| --- | --- |
| Docker 首次部署 | `cd /etc/relay-price && sudo docker compose run --rm -it app python server.py --init-auth`，按提示设用户名和至少 8 位密码（详见 `DEPLOY.md` 3.2） |
| systemd / 源码首次部署 | 先停服务，再 `python server.py --init-auth`，跑完启动 |
| 服务已经在跑 | 浏览器打开服务 →「系统设置 → 访问保护」→ 填用户名和新密码 → 开启 |
| 想关掉 | 同一页点「关闭访问保护」，需要输入当前密码 |
| 忘记密码 | 停服务后重跑 `--init-auth`，它会覆盖 `auth.json`，再启动 |

`--init-auth` 是交互式的（Docker 里必须带 `-it`），它会写 `auth.json` 并取实例锁，所以服务在跑时要先停。
没有终端（CI、面板、Agent 代跑）时带 `-it` 会直接卡住，改用 `-T` + `--auth-stdin` 从标准输入读用户名和密码，写法见 `DEPLOY.md` 3.2。

**没开访问保护会怎样**

- `server` 模式：**拒绝启动**，退出码 1，控制台直接告诉你该执行哪条命令。
- `local` 模式：只监听 `127.0.0.1`，外部本来就访问不到；如果手动把监听地址改成 `0.0.0.0`，同样拒绝启动。
- 万一服务被反代或内网穿透包出去，而访问保护又没开，来自回环之外的请求一律返回 403（提示里带开启方法）。
- 确实打算让前面的反向代理负责鉴权，设 `RELAY_ALLOW_UNAUTHENTICATED_REMOTE=1` 放行——前提是你确认反代那一层真的开着。

**认证开启后的机制**

`/login`、`/login.js`、`/healthz`、`/api/ping`、`/api/auth/challenge`、`/api/auth/login`
是匿名入口；其余业务接口与 `/data/*` 在未登录时返回 401，`/` 跳转 `/login`。
会话 Cookie 为 `relay_session`（`HttpOnly; SameSite=Strict`），全部来源都是 https 时才加 `Secure`，
空闲 30 分钟或满 12 小时失效。写请求除 Origin 外还要带 `X-Relay-CSRF`。
口令用 scrypt 派生后存 `auth.json`；登录要带一次性挑战，失败按来源 / 账号 / 全局三层限速并逐次退避，
成功和失败都会写进 `logs/`（失败行只有来源和用户名，不含密码）。

`RELAY_ALLOWED_ORIGINS` 必须与访问协议一致：用 `http` 访问却把来源写成 `https://`（或反之），登录后会立刻被打回 `/login`。

### 健康检查与停机

`GET /healthz` 只探测状态目录可写，不读快照、不发站点请求，返回 `{"ok": ..., "version": ...}`；目录不可写时返回 503。
收到 `SIGTERM` / `SIGINT` 后先停止任务与调度，45 秒预算内收尾；超时保留 journal 中未确认的写操作，**不会重放**。容器 `stop_grace_period` 设为 60 秒，不要调小。

## 已知边界

- **站点开了验证码 / 滑块 / 二次验证时，脚本无论如何登不进去**（目前已知 `ai.jidog.com` 要 captcha）—— 只能用 Cookie，让脚本替你过验证是不可能的，这条路不绕弯子。
- Cookie 有有效期，站点重新登录后旧 Cookie 会失效，表现为「取不到」；重新复制一次即可。
- 只刷新某一个站点时，**其他站点已有的数据会原样保留**，不会被写成「未配置」。
- 模型跨站归类用「归一化 + 相似度」，已加版本号与词汇约束防止误合并，但建议点开看原始模型名确认。
- 导出到 CC Switch 时，**余额查询脚本按站点类型分别生成**：New API 站要有管理令牌（或账号密码登录拿到的令牌），Sub2API 站用模型 API Key 查 `/v1/usage`；Cookie 登录的 New API 站仍能导出，只是不带用量脚本（生成结果里会写明）。拿不到**已确认的单位与授权**时不硬凑脚本，宁可不带。
- CC Switch 的 `apiFormat` 参数要 **4.0.10 以上**才认，版本低时页面会禁用这一项，避免生成一条被拒的链接。
- 动态分档计费按表达式选择**短上下文那档**作展示基准（例如 `len >= 272000 ? 高价档 : 低价档` 取低价档），并把表达式原文留在数据里；表达式无法解释时显示为未知，不当成免费，也不参与最低价排名。
- 访问保护是**单账号**，没有多用户、角色和两步验证；忘记密码只能停服务重跑 `--init-auth`。需要多人分权时应该放在带鉴权的反代后面，或者各开一个实例。
